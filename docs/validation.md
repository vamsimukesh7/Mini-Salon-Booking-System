## Genuine failures corrected

1. Fallback combined Haircut + unsupported Manicure returned the haircut-only total.
   Added a conservative guard against unrecognized bundle vocabulary, preserving
   runtime catalogue changes; regression now passes. See the iteration note.
2. Inline validation text changed an input's accessible name. Added stable field
   names; the browser flow now fills the invalid field and proceeds correctly.
3. Refreshing the dashboard returned to booking. Navigation now restores the view
   using a URL hash while data reloads from the API.
4. The initial test runner version stalled under Node 24. Updated Playwright to
   1.64.1. The environment's installed Chromium is used because browser-download
   domains were denied by the egress policy.
5. Read-only default npm cache prevented installation. A writable `/tmp` cache is
   included in the tested cloud installation instructions.
6. Docker builds initially lacked the platform proxy DNS mapping and CA trust.
   Supplied the proxy host mapping, standard proxy build arguments, and a trusted
   CA through a BuildKit secret. Both dependency installers then passed with TLS
   verification intact. No verification bypass was used.
7. The final non-root image check caught private workspace file modes retaining root
   ownership in copied source directories. Added explicit COPY ownership, then
   verified non-root SQLite initialization and reran the PostgreSQL container
   workflow successfully. Private `.env` and build CA files are absent from the image.

## Reproduce PostgreSQL checks (optional)

Use only a local disposable test server. The fixture requires CREATE DATABASE and
creates unique `atelier_test_*` databases, dropping those at teardown. Never supply
an application production connection. On this machine the checks were run with:

```sh
docker run -d --name atelier-test-postgres \
  -e POSTGRES_HOST_AUTH_METHOD=trust \
  -p 127.0.0.1:55432:5432 postgres:17-bookworm
TEST_POSTGRES_URL=postgresql://postgres@127.0.0.1:55432/postgres \
  .venv/bin/pytest backend/tests -q
docker rm -f atelier-test-postgres
```

The trust setting is only for this disposable loopback-bound test container;
use provider-managed credentials and TLS for hosted application storage.
